以下の情報を基に、保守運用案件で使えるテスト観点を作成してください。

対象:
{{input}}

# 必須観点
1. 正常系（主要ユースケース）
2. 異常系（入力不正、外部障害、タイムアウト）
3. 境界値（最小/最大/桁数/日付境界）
4. 権限・ロール差分
5. 既存機能への影響（回帰）
6. 運用観点（監視、ログ、アラート、リカバリ）

# 出力形式

## 1. テスト方針サマリ
- 対象範囲
- 非対象範囲
- リスクが高い領域

## 2. テスト観点一覧
- 以下の列を含む表形式で出力
  - 観点ID
  - 区分（正常/異常/境界/権限/回帰/運用）
  - 観点
  - 期待結果
  - 優先度（高/中/低）

## 3. 追加で必要な確認事項
- 不明点を最大10件
- 各項目に「なぜ必要か」を1行で追記

# ルール
- 実行可能な粒度で具体化する
- 曖昧な表現（適切に、十分に、など）は避ける
- 情報不足時は、推測より確認質問を優先する
