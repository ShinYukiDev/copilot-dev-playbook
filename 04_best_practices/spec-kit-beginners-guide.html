Spec Kit 入門ガイド

Spec Kit は、最初に仕様を明確にしてから、計画・タスク・実装へ進めるための仕組みです。AIを使うときに起きやすい「何を作るかが曖昧なまま進む問題」を減らし、初心者でも同じ手順で再現しやすい開発・改善の流れを作れます。

仕様先行 手順の標準化 初心者でも再現しやすい Copilot で使える 業務改善に向く

1. Spec Kit とは

ひとことで言うと

Spec Kit は、「何を作るか」を先に文章化し、それを元に AI が実装まで進めるためのオープンソースの仕組みです。

  • 仕様を中心に考えるので、途中で目的がぶれにくい。
  • 計画やタスクを分けるので、初学者でも進め方が見えやすい。
  • 人による説明の差を減らし、引き継ぎやレビューに使いやすい。

公式サイトから押さえるポイント

  • Spec Kit は Spec-Driven Development を前提にしている。
  • 仕様は「書いて終わり」ではなく、実行に進めるための土台になる。
  • AI を使っても、何を作るかを人が先に定義する考え方が重要。
  • 導入後は、必須: /constitution → /specify → /plan → /tasks → /implement の順で進める。
  • 品質向上のために 任意: /clarify, /analyze, /checklist を組み合わせる。

2. なぜ業務で役立つのか

作業の抜け漏れを減らす

調べる項目や確認条件を先に書くため、口頭ベースのやりとりより漏れが起きにくくなります。

引き継ぎがしやすい

仕様・計画・タスクが残るので、担当者が変わっても経緯を追いやすくなります。

AI 活用を標準化できる

毎回の聞き方や進め方を揃えられるため、個人差を減らして使えます。

3. 図解: 全体の流れ

Spec Kit は、まず必須コマンド5つで進めます。必要に応じて任意コマンドを補うと、品質と確信度を上げられます。

必須（★）: /constitution → /specify → /plan → /tasks → /implement
任意: /clarify（plan前）, /analyze（tasks後〜implement前）, /checklist（plan後）

4. 導入手順

公式サイトの流れを、初学者向けに最短でまとめると次の通りです。

1. CLI を導入する

uv を使って specify-cli を入れます。導入確認には specify --version を使います。

2. プロジェクトを初期化する

specify init で既存または新規のプロジェクトに Spec Kit を設定します。Copilot 連携も選べます。

# インストール
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git

# バージョン確認
specify --version

# プロジェクト初期化
specify init my-project --ai copilot

5. コマンド別の具体例

例題は todoアプリの開発 です。必須コマンドと任意コマンドが分かるように整理しています。

必須: /constitution, /specify, /plan, /tasks, /implement
任意: /clarify, /analyze, /checklist

constitution の例（必須）

/constitution
すべてのドキュメントは日本語で作成・更新する。
機能は小さく分けて実装する。
UI はシンプルで、操作手順が分かりやすいことを優先する。

specify の例（必須）

/specify
todoアプリを開発したい。
ユーザーはタスクを追加、編集、完了、削除できる。
一覧では未完了と完了を分けて表示したい。

clarify の例（任意）

/clarify

plan の例（必須）

/plan
- WinForms（VB、.netframework 4.8）を利用する。
- DBはSQLiteを利用する。
- 画面は入力欄、未完了一覧、完了一覧の3領域で構成する。

/tasks

analyze の例（任意）

/analyze

implement の例（必須）

/implement

8. 初心者がつまずきやすい点

つまずきポイント

  • 最初の仕様が広すぎる。
  • 技術の話から先に始めてしまう。
  • 曖昧なまま /plan に進んでしまう。

対策

  • まずは 1 業務、1 機能、1 画面に絞る。
  • 「何を・なぜ」を先に書く。
  • /clarify を使って疑問点を洗い出す。

9. 業務で広げるときの考え方

最初から全部に広げるより、小さく始めて、効果が出た型を横展開するほうが失敗しにくいです。

  • まずは問い合わせ対応や小さな改善案件で試す。
  • 手順が安定したら、チームの共通テンプレートにする。
  • うまくいった書き方や確認項目を constitution に戻して更新する。

補足: 公式サイトでは GitHub リポジトリ、Discussions、動画、導入手順が案内されています。詳細は speckit.org を確認してください。

10. まとめ

Spec Kit は、仕様を先に固めてから AI で実装へ進むための仕組みです。 初学者にとっては、作業の順番が見えること自体が大きな価値になります。業務では、問い合わせ対応、手順整備、小規模な改善案件から始めると効果を実感しやすいです。

重要なのは、AI に任せることではなく、何を作るかを人が明確にすることです。
