Mermaid記法トレーニング（ハンズオン）

対象: Markdown初学者 / 目的: 保守部門の設計書・手順書で図を自力作成できるようになる

学習ゴール

1. flowchart / sequenceDiagram / stateDiagram の用途を区別して使える

2. それぞれの基本記述で業務ドキュメント向けの図を作成できる

3. エラー表示を見て記法を修正できる

フローチャート（flowchart）

説明

処理の流れ、分岐、担当引き継ぎを表す図です。障害一次対応フローや定型作業手順の表現に向いています。

記述方法: 先頭に flowchart と向き（TD など）を書き、--> でノードをつなぎます。分岐は {条件} を使います。

向きの指定: TD は上から下、LR は左から右に流れるレイアウトです。手順書では TD、横に比較したい図では LR が使いやすいです。

例

flowchart TD
  A[障害受付] --> B[一次切り分け]
  B --> C{復旧できた?}
  C -->|Yes| D[完了報告]
  C -->|No| E[二次対応へ連携]
  D --> F[チケットクローズ]
  E --> F

演習

演習: 「定期バックアップの実施フロー（成功/失敗の分岐あり）」を書いてみましょう。

プレビュー

エラー例: flowchart TD の書き忘れ、矢印 --> の不足、ノード括弧の閉じ忘れ。

シーケンス図（sequenceDiagram）

説明

誰が誰に、どの順序で連絡・処理を行うかを時系列で表す図です。メンテナンス連絡や問い合わせ対応の流れに向いています。

記述方法: 先頭に sequenceDiagram を書き、participant で登場者を定義します。送信矢印は ->>、返信は -->> で記述します。

例

sequenceDiagram
  participant OP as 運用担当
  participant US as 利用部門
  participant SYS as 対象システム
  OP->>US: メンテナンス通知
  US-->>OP: 了承
  OP->>SYS: 停止
  OP->>SYS: 作業実施
  OP->>SYS: 起動確認
  OP->>US: 完了連絡

演習

演習: 「利用者から障害連絡を受け、運用担当が調査して一次回答する」流れを書いてみましょう。

プレビュー

エラー例: participant 名の未定義、矢印記号のタイプミス。

状態遷移図（stateDiagram）

説明

対象の状態がどの条件・イベントで変わるかを表す図です。障害管理チケットやジョブ実行状態の管理に向いています。

記述方法: 先頭に stateDiagram を書き、A --> B: 条件 の形式で遷移を記述します。開始は [*] を使います。

例

stateDiagram
  [*] --> 監視中
  監視中 --> 障害検知: アラート発報
  障害検知 --> 対応中: 担当アサイン
  対応中 --> 復旧: 修正完了
  復旧 --> 監視中: 監視再開

演習

演習: 「チケットの状態（新規→調査中→対応中→完了）」を状態遷移図で書いてみましょう。

プレビュー

エラー例: stateDiagram の誤記、遷移の矢印不足。
